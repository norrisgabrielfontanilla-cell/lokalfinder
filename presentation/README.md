# Lokal Finder: business presentation

`Lokal_Finder_Premium_Presentation.pptx`: 17 widescreen (16:9) slides, fully editable in PowerPoint, with real slide
transitions, real object animations, speaker notes, a native chart, the actual Lokal Finder logo, real screens of the live app
and the real store and food pictures the sellers uploaded.

Everything in this folder is generated by code, so the deck can be rebuilt, restyled or corrected in one place.

```
cd presentation
npm install
npm run assets      # (optional) re-capture the app screens, logo, mockups, artwork, icons
npm run build       # -> Lokal_Finder_Premium_Presentation.pptx
python3 tools/verify-package.py Lokal_Finder_Premium_Presentation.pptx --lo     # proves the motion is in the file
```

## Design system

* **Canvas** 13.333 x 7.5 in, 0.75 in margins, 12-column grid (`src/theme.js`).
* **Colour** (theme colours written into the file, so *Design > Variants > Colors* restyles it): ink `0D2B1A`, forest `0F4A32`,
  mist `F0F7F3`, green `0E8A5A`, mint `12B76A`, amber `F59E0B` (the one warm accent: emphasis and "to be proven"),
  brand green `1A6B4A`, sage `6B8F7A` (a darker `4A6B5A` is used automatically for text on light slides), gold `F5C842`.
* **Type** Cambria (editorial serif, headlines and key numbers) and Calibri (body), both shipped with Office. The brand fonts
  (Fraunces, Plus Jakarta Sans, Bricolage Grotesque) are not installed on most machines and PowerPoint cannot reliably embed
  them, so editable text uses the safe pair; the wordmark and the app screens are pictures and keep the brand fonts.
  Scale: 120 / 70 / 40 title / 28 / 22 / 20 lede / 17 body / 15 label / 13 / 12 footnote. Nothing smaller than 12 pt.
* **Layouts** `LF_COVER`, `LF_CLOSE`, `LF_VISION` (full-bleed art), `LF_DARK`, `LF_LIGHT` (+ `_L` narrow-title variants).
  Titles are real title placeholders; each slide has an eyebrow above the title, an italic accent word in the title,
  one footnote line next to the logo mark, and a page number bottom right. Phones that rise from the bottom edge keep clear of
  the footer corners.
* **Rhythm** dark and light slides alternate; artwork slides open and close the story.
* **Motif** the "ripple": concentric rings radiating from a pin (proximity), used in the artwork, the market slide and the vision slide.
* **Images** phones are framed identically; art is full-bleed with a scrim on the text side; every picture has alt text.
* **Chart** one native, editable column chart (automated checks by release), mint bars, the latest release in amber, no gridlines.

## Motion (real PowerPoint transitions and animations)

pptxgenjs cannot write transitions or animations, so `src/motion.js` post-processes the finished package and writes the
same `<p:transition>` and `<p:timing>` elements PowerPoint writes. `tools/verify-package.py` checks them.

* **Transition** Fade, 0.6 s on every slide (0.9 s on the cover and closing, 0.8 s on the vision slide), with an `mc:Fallback` for older PowerPoint.
* **Entrance effects** one vocabulary only: *Float In* (rises about 5% of the slide height while fading, 0.55 s) for headlines, cards
  and phones; *Fade* (0.5 s) for supporting text and marks; *Wipe* (0.7 s) for lines, paths, timelines and the chart.
* **Build** every slide builds itself in about 2.3 to 3.7 s after its transition: the first effect is *After Previous* and the rest are
  *With Previous* with a stagger, so a presenter never has to click to reveal content. Process steps and diagrams arrive in reading order.
* No emphasis, exit or path animations, no sound, nothing spins or bounces.
* 409 animated objects in total. Verified in the package: unique time-node ids, every target is a real shape, `bldLst` entries match
  text/auto shapes and the chart, each slide has a transition. A LibreOffice round-trip independently found the same number of animation
  nodes (409 `anim:set` plus the 17 slide transitions).

**Not tested:** playback in Microsoft PowerPoint itself (it is not available in the build environment). The XML follows PowerPoint's own
structure and passes the OOXML schema checks, but visual timing has not been watched live. If PowerPoint offers to repair the file or a
build looks wrong, open Animations > Animation Pane on that slide; every effect is a normal, editable PowerPoint animation.

## Real pictures (added 2026-10-29)

The store and food pictures are **not in this repository**: they live in the app's database, which the Claude environment cannot reach.
They were read from the live app by one-off, read-only GitHub Actions runs (every request that is not a GET aborted; nothing in production can
change; no orders, chats, customer or seller contact data). How the runs work, what the live catalog held and what was left out is in
`../pamphlet/README.md` ("How the real pictures were collected"). For the deck, a second run added the phone screens, including a real checkout
page. The temporary workflow is in git history (commit `90700f0`); the tools are in `../pamphlet/tools/`.

* `node tools/make-live-assets.js` crops the twelve food pictures and five logos (`assets/live/`) from `../pamphlet/tools/out-live`, which is not committed.
* `assets/screens/live-home.png`, `live-store.png`, `live-checkout.png` are the real screens; `node tools/make-mockups.js` frames them like the others.
* Slides 1, 4 and 5 (inside the real screens) and slide 10 show real store names, logos and food pictures. The sellers did not agree to appear in a presentation: ask them before the deck leaves the company.

## Rebuilding and QA

```
node build.js            # all slides, or `node build.js 07` for one
tools/qa.sh              # build + render to out/render/slide-NN.png (needs LibreOffice and PyMuPDF)
node tools/contact.js    # contact sheet of the render
python3 tools/verify-package.py Lokal_Finder_Premium_Presentation.pptx --lo
```

LibreOffice shows the final state of each slide (it does not play animations). It also needs Carlito and Caladea installed to
reproduce Calibri and Cambria widths. The peso sign (U+20B1) may come from a fallback font on computers where Cambria lacks it.
